A syntax error must be found before the old result is opened for replacement.

## The working parts

DEST selects CHAR output: zero writes the console and one stores into OUTBUF. OUTBUF, OUT1, OUT2, and OUT3 are consecutive declarations forming 1024 bytes. OUTCOUNT is checked before each store. The pointer is ADDR OUTBUF plus a valid byte offset. VALUE retains the character while that pointer is formed.

CHAR still checks console failures. Its buffer path changes VALUE and OUTCOUNT, but not WORK or PLACE. After recognizing the empty program, the driver buffers its IR, then displays the count and complete contents. It creates no result file at this checkpoint.

## Build the stopping point

```dos
CHECK IRKEEP
```

Enter `R14` at `IR source name:`. Require `OK R14.ASM 15100 text bytes` and PASS. Then run `CHECK ASMKEEP`, enter `R14` at `Source name:`, and require `OK 03353 bytes` and PASS. Save the source and executable before testing.

## Acceptance check

Create `T14.RIL` with COPY CON or a plain-text editor. Enter this exact text and finish with Ctrl-Z and Enter:

```rill
fn main() {}
```

Run `COPY T14.RIL SOURCE.RIL`, then `CHECK R14`.

Apart from DOS command echo and the checker's separating blank line, require:

```text
BUFFER 00018
LABEL MAIN
HALT
PASS
```

This is a diagnostic stopping point. It does not create RESULT.IR.

## A rejection check

Create X14.RIL with this separate test:

```rill
fn main() {
```

Copy X14.RIL to SOURCE.RIL, then run CHECK R14. Require:

```text
ERROR 00002 CODE 00002
FAIL
```

An unexpected PASS is a failed rejection test.

## If the result differs

Check both halves of keyword spellings, required delimiters, and saved names or operators. Compare RESULT.IR with the printed text before translating it. A source error and a result-write error have different effects on an old file.
